Comparison adds a second thing colour has to encode, and it is more important than type: which dataset is this. Every chart now carries two series, so the four-step blue in 6b can no longer be spent on segments — the steps get eaten by the series. Comparison also invents a third meaning — went up / went down — and that must not borrow olive and rust, because a delta is not a verdict. More rows is neutral. More missing values is not. Rule at the bottom.

Three of those four moved, and only one is coloured. Rows went up 17.5% — that is a fact, printed in ink with an arrow, because nobody can say whether it is good. Missing values went from 8.1% to 11.3%, which crosses the warning threshold, so it turns ochre. Columns did not move and says so.

Turn 6 · colour

Should every chart just be blue?

Settled from last round: 5b axis treatment, 5f description. On colour — yes, and I think you've caught a real problem. Short answer below, then the two side by side.

Why they differ today

Inherited, not decided. Your current report already assigns a colour per type in the summary donut — numeric #4ea3f1, categorical #8ac926, datetime #ffca3a, boolean #ff595e — and I carried that into the per-column charts. In the donut it is doing work: four segments have to be told apart. In a card it is doing none, because the badge next to the column name already says which type it is.

Why blue-only is better

Because right now one colour means two things. Olive means "categorical" on a chart and "passes" on a flag. Rust means "boolean" and also "bad". A red bar and a red warning chip sit in the same card meaning unrelated things. Painting all data blue frees olive, ochre and rust to mean one thing only — quality — so colour on the page becomes a signal instead of decoration.
