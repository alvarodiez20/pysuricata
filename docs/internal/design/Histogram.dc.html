Turn 13 · histogram geometry

The chart got the width. It should not take all of it.

Your chosen approach is right, and I have already built it — the tails and outlier charts in Details are SVG bars with HTML labels at percentage offsets, for exactly this reason. So this turn takes your five questions as the brief rather than re-arguing the architecture, and adds one defect the split will otherwise introduce.

Note Every 25-bin chart below is the real Age output — 714 values, 0.42 to 80 years, peak 83 — drawn in the proposed architecture at the width shown, and the frames are literal widths. The 50-bin series in 13b is derived by splitting those bins, so its counts are illustrative; its axis max is recomputed from its own peak, as the renderer does.
1 · Composition at wide widths

A 1,100 × 210 plot is 5.2:1. At that ratio the average slope of any distribution flattens toward horizontal, and every column starts to look like a gentle mound — the letterbox is doing the same damage the blank space was, just less visibly. But the fix is not height: twelve columns each 400px tall is a report nobody scrolls.

The width past about 800px also buys very little. At 800px, 50 bins is 16px each; at 1,100px it is 22px. Nobody reads a 22px bar more accurately than a 16px one. So the question is what to do with the 300px, and the answer is not "stretch the bars into it".

PRO

CON

Deliberately leaves width unused at 1600px+, which will read as a bug to anyone who filed the original issue. And a second column means a second breakpoint to maintain, at 1180px, where the controls have to move back.

2 · Tick density, decided by CSS

This one has a clean answer, and it only exists because the labels are now HTML. Render every tick you would ever want, tag the optional ones, and let a media query drop them. The renderer writes 9 x-ticks and marks alternates data-tier="2"; a third pass marks the ones that survive to 3. CSS picks the tier for the width. No variants, no JS, and the extra bytes are four short strings per column.

/* 9 ticks written once. Tier 1 always shows. */
@media (max-width: 760px) { .hist-x [data-tier="2"] { display: none } }  /* → 5 */
@media (max-width: 440px) { .hist-x [data-tier="3"] { display: none } }  /* → 3 */

3 · The gutter · 4 · Where the captions live
13d

44px, because counts abbreviate

A y tick is a row count, and nobody reads seven significant figures off an axis. 1,234,567 should never appear there — 1.2M should. Cap the label at four glyphs and the gutter is a constant.

{{ g.raw }} {{ g.shown }} {{ g.note }}

Four glyphs of 11px mono is 27px, plus a 5px tick and 8px of air: --hist-gutter: 44px. Fixed at every width, so the plot's left edge never moves between columns and the bars of two cards line up down the page.

Exact The precise peak stays in the caption — peak 83 rows at 26–29 — so abbreviating the axis loses nothing.
CON

A reader cannot tell 1.2M from 1,249,999, and on a bar chart of counts that occasionally matters. It also needs _format_tick_label_standardized to guarantee four glyphs rather than merely prefer them — today it can emit 12.5K, which is five.

13e

The x unit moves. ROWS stays.

ROWS is anchored to the gutter, so it survives any width — it is 44px from its axis whatever happens. YEARS at the right end does not: at 1,100px the two captions are a metre apart and stop reading as a pair.

Today, at 1100px
ROWS YEARS
two labels, no relationship visible between them
Proposed
ROWS age in years · 25 bins · peak 83 rows at 26–29
one caption under the axis, left-aligned to the plot origin

It reads as a sentence, it carries the bin count and the peak alongside the unit, and it is where a reader's eye already goes after the axis. This is the line 13a and 13b both use.

CON

A caption below the axis is further from the x labels than an in-axis unit was, so on a very tall stack it can read as belonging to the next element. It also puts the unit in prose, where derive_x_unit returning None now has to read gracefully — 25 bins · peak 83, with no unit clause at all.

13g

The gap between bars will vanish

Not in your brief, and it will bite on the first mobile render. _render_bars sets bar_w = max(1, bar_width - 1) — a 1-unit gap in viewBox space. Under preserveAspectRatio="none" that unit scales with x like everything else.

Plot widthx scale1-unit gap becomes
{{ g.w }} {{ g.scale }} {{ g.gap }}
Fix Stop drawing the gap. Draw the bars edge to edge and separate them with a --paper stroke carrying vector-effect: non-scaling-stroke. Adjacent bars contribute half a pixel each, so the separator is exactly 1px at every width — the same trick you already planned for the gridlines. Every chart on this page is drawn that way.

It also removes the max(1, …) floor, which today silently makes a 50-bin bar 1 unit wide on a 420-unit canvas and drops the gap to zero anyway.

CON

A paper-coloured stroke is invisible against any other background, so a bar overlapping something else — a highlighted bin, a selection — needs the stroke reconsidered. Nothing does that today.
